# V1 产品范围

V1 是一套供单个可信用户自托管的真实数字资产目录，而不是继续以 CLI、固定样例或原型界面代替产品。它必须使用真实文件和真实官方来源完成识别、采用、浏览、刷新、审阅与基础消费闭环，并在进程重启后保留权威状态和可审计历史。

## 已确认的用户旅程

- 用户可以配置受观察目录和适用来源凭据，通过普通扫描、自动刷新、添加内容或定向识别接入内容；这些入口使用同一资产刷新工作流和提议到决策路径。
- 用户可以在正式设置中建立和维护需要授权的在线来源；公开来源无需配置，环境变量和挂载的私有文件只是部署时的可选引导或覆盖方式，不是普通使用的唯一入口。各来源只解释自己的授权输入和生命周期，私密值由产品管理的本地私有存储保管，不进入数字资产、来源记录、普通目录状态、诊断或固定样例。可信单用户 V1 不建立加密保险库、账户隔离或通用凭据模型。
- 用户可以把容器内可见的绝对路径登记为只读“文件位置”，并为每个位置选择链接跟随策略和允许的链接目标位置。添加内容、定向识别、手动刷新与自动刷新都只选择这些位置内的有限范围；自动刷新只是独立附加的周期安排，停用它不会撤销文件访问。产品不建立宿主机与容器路径的映射层。
- 部署必须在应用启动前提供唯一的产品数据目录；空目录可以初始化 SQLite 数据库，正式设置不能在线改变这个自举位置。SQLite 数据库、托管产物、来源连接私有存储和持久配置位于其明确子区域，可删除缓存具有独立边界。改用另一目录表示打开另一套安装；V1 迁移采用停机后整体移动，不复制受观察文件。
- V1 唯一正式生产部署是文档化的 Docker Compose 单容器：一个 `/data` 可写产品数据卷，若干以只读方式挂载并在产品内登记的受观察目录。镜像以非 root 用户运行，NAS 读取权限和 UID／GID 映射由部署者配置；容器不发现宿主机路径或获得媒体写权限。Kubernetes、多容器 worker、systemd 裸机、桌面安装包和厂商 NAS 套件暂不支持，`pnpm dev` 只用于开发。
- V1 提供并实际演练停机整体备份与恢复：停止应用后复制产品数据目录，恢复到兼容应用版本并重新提供登记过的容器挂载路径。备份覆盖 SQLite 数据库、托管产物、持久配置和来源连接私有存储；明确可删除的缓存可以重建，受观察原文件仍由用户自己的存储方案保护。验收恢复后的浏览、历史、来源连接、手动刷新和直接播放，不实现在线、增量、云端或跨安装合并。
- 可信的确定结果可自动采用；不确定、冲突或需要审阅的结果进入统一检查工作区和待处理事项。
- 用户可以浏览数字资产、关系、可用产物和已经采用的来源事实，并执行“刷新元数据”与“重新刮削”；操作结果可审计，需审阅的结果在采用前使用正式资产视图投影展示。
- 正式 Web 界面覆盖日常旅程，并为 DLsite、FANBOX、出版物、番剧和电影提供适合其信息结构的资产视图；这不会在数字资产上下文中建立对应媒体类型。
- 用户可以下载一个精确且当前可访问的产物修订版。交付层以附件方式流式传输并隐藏服务器路径；尚无确认修订版的本地文件只在本次请求时渐进计算摘要，确认过程中变化则失败并要求普通刷新。该能力可服务出版物、FANBOX 附件、脚本和其他产物，但不提供浏览器内联打开、临时 PDF／EPUB 阅读器、下载历史、托管副本、整作品 ZIP 或导出布局；资产、目录和文件树的成员范围不能由下载接口猜测。
- 受观察目录保持只读；目录整理、导出和元数据写回不属于当前已确认的 V1 发布门槛。

## 架构发布门槛

- 来源刷新运行、每个来源覆盖范围的来源刷新变更集、审阅、过期检查、取消和终态由数字资产上下文拥有权威语义；工作流执行只协调并引用，SQLite 适配器只负责持久化和条件追加。
- 每个资产视图与后台工作分别提供一份完整信息需求，并通过同一应用层履行和信息就绪状态路径获得信息；不再从子组件片段合成通用超集，也不允许交互与自动扫描获得不同信息。
- 能力声明包含完整种类、版本和解释合同；产品应用层校验固定产品能力组合的唯一性与合同兼容性，工作流恢复和历史来源覆盖所有实际参与能力。
- 可执行入口是最外层组合根，同时选择纯组合模块和对应交付模块，再通过 `runProduct(configuration, delivery)` 把产品应用入口注入交付模块。Web 与 CLI 的交付实现是独立包，交付模块不依赖组合模块，其完整传递依赖闭包不能到达集成或基础设施适配器。
- 产品应用层拥有固定产品策略和 Bangumi 授权、FANBOX 配置等交付无关用例；组合模块只选择适配器、完成装配并持有资源生命周期。来源协议与授权状态机归各自适配器，不引入按来源字符串查找能力的通用运行时注册表。
- Turborepo Boundaries 直接表达稳定包角色和依赖方向。新包图成立后，旧的别名越界、持久化泄漏、来源边分析、渲染器隔膜及其专用脚本和重复任务入口全部硬删除，不保留兼容包装。
- 正式 V1 可以从产品内建立、检查、替换、撤销或重新授权所需来源连接；OAuth、浏览器导出凭据和访问令牌等差异保留在各自能力与设置界面。秘密值通过应用层拥有的窄私密状态端口访问，不能进入来源记录、工作流执行或通用凭据模式。
- 文件位置、来源连接和适用设置的变更无需重启应用。新的工作流执行在开始时冻结有限范围、非私密配置版本、能力声明和规划输入；运行中的执行不会因设置变化被静默重新规划或自动取消。
- 应用启动时检查所有非终态长工作流执行。兼容执行从最近持久断点恢复，等待审阅的执行继续等待；无法恢复者进入明确中断终态并保留已提交结果和原因。恢复不回滚领域结果、不自动开启替代刷新，也不增加网络重试、分布式队列或 exactly-once 基础设施。
- V1 由 Web 进程内唯一执行宿主统一托管手动、添加内容、定向识别和自动刷新等长执行。HTTP 在执行已持久化且被宿主接受后立即返回编号；关闭时停止新操作并允许任务停到安全断点。执行宿主不建立持久队列、重试策略或第二套状态模型。
- 只有产品数据目录、SQLite 结构或完整性、必要迁移、能力声明唯一性与合同兼容性等核心前提失败才阻止正常启动。单个来源连接或文件位置故障只使依赖工作明确不可用，不能抹去既有事实、声称文件消失或制造错误重启循环。
- 固定真实语料的 29 个逻辑根全部通过只读安全门；其中 24 个通过当前真实官方来源完成识别：8 个 DLsite 音声、5 个 FANBOX 帖子、6 个 EPUB 出版物根、1 个包含三部 PDF 作品的系列根、2 部番剧和 2 部电影。其余 5 个根保持安全但未识别。oracle 只验证结果，不能提供采集响应；缺少网络或来源时真实门失败。
- SQLite 是 V1 持久化存储，Drizzle schema 是数据库结构的唯一代码来源。发布前开发数据库可直接演进；首次正式发布时冻结基线，此后正式数据库只通过向前迁移升级。`@digital/sqlite` 实现应用层拥有的窄持久化端口，不向 Web 暴露通用数据库包。
- 正式容器采用 YKDZ/template `vike-app` 的生产准备形状：普通入口先运行独立部署的 Drizzle 迁移，另提供仅准备和已准备后启动模式；未准备、版本过新、迁移失败或完整性失败的数据库不能服务请求。
- 生产 Web 分离存活检查（liveness）与数据库就绪检查（readiness）。就绪要求迁移、核心数据库检查、能力声明校验和非终态执行恢复分类完成，但不等待长执行结束；单个来源或文件位置故障只是局部降级。
- 持久化端口由应用用例、原子提交和明确查询塑形，不从领域类型或数据库表机械生成。不可变证据、版本化输入和审计载荷可以使用显式版本 JSON，但权威领域生命周期不能只存在于查询投影或工作流 JSON 中。
- 每个受观察逻辑根实现 ADR-0037 的明确符号链接策略。跟随目标必须位于当前根或另一个明确授权根；链接别名保持普通位置，循环、断链、越界、权限错误和扫描中变化产生诊断与不完整覆盖。
- 文件位置登记独立于自动化意图，属于应用配置而不是领域目录、媒体库或资产分类。移除登记只撤销后续扫描、播放和读取权限并停用依赖自动刷新；登记身份、历史执行、位置、数字资产、关系、来源事实与决定继续保留。
- 正式资产视图与播放器保持选择、完整投影和交付映射局部，不使用运行时插件注册。具体视图直接消费资产展示投影，不为单个渲染器建立专属隔膜或源码检查器。
- 当前数字资产、工作流执行历史和当前待处理事项使用用途明确的分页应用查询；普通浏览不遍历全部永久审计历史后在 Web 去重，也不预先建立未证明必要的物化投影。
- 不以文件长度为理由整体重写应用层或 SQLite；重构沿真实用户旅程建立职责明确、可独立验证的模块，并保持应用层拥有的事务与条件追加语义。

## 正式界面采用方式

- 不继续维护一个覆盖全部产品的巨大原型。一次只选择一个完整界面或紧密相关的用户旅程，使用真实形状的数据覆盖正常、加载、空白、部分可用、阻塞、失败和响应式状态。
- 每个原型现场验收视觉、用词和交互后，立即拆分并应用到正式视图组件与路由，接入真实资产展示模型，补齐回归验证并删除该原型路由与专用固定数据，然后才进入下一个界面。
- 应用框架、视觉变量、规范用语和 shadcn-vue 组件是正式维护的共享基础，不由每个原型重新创建；原型仍是设计验证产物，不是领域事实、长期兼容界面或生产架构。

## 首个播放切片

- V1 提供真实可用的直接播放，而不是只预留播放器按钮或未被使用的抽象。
- 首个验收对象是包含多个文件与目录层级的 DLsite 音声作品，播放体验参考 Kikoeru 的作品文件树、当前播放队列和常驻播放控制，但不复制其按路径和扩展名建立身份的实现。
- 用户可以从作品内明确选择可播放文件；选择一个音频时以当前文件树层级的可播放文件形成临时播放队列，并从所选文件开始顺序播放。队列支持“添加到播放队列”和“下一首播放”，跨页面导航保留但无需在关闭浏览器后恢复。
- 播放队列的顺序和目录分组只属于资产展示，不建立收藏集、实体关系、元数据断言或资产层级。队列项引用精确产物修订版，文件名可用于展示但不成为元数据或身份。
- V1 提供播放、暂停、进度跳转、上一首、下一首、音量和当前队列；随机、循环、睡眠定时和保存播放列表不作为发布门槛。
- 每个单独音频文件的播放位置和完成状态绑定到精确产物修订版并自动保存；内容变化后，旧位置不会静默应用到新修订版。当前目录或播放队列可以派生本次选择的进度，但无法稳定定义全作品进度的资产不记录作品级进度，也不从目录名称、全部文件或替代编码推断它。
- V1 直接播放浏览器原生支持的本地音频和视频；不支持的容器或编码显示明确原因。
- 交付层通过同一套媒体中立、支持 HTTP Range 的读取通道提供播放呈现，使浏览器能够按需取得字节、开始播放和跳转位置，而不必先下载完整文件。流地址不暴露或接受任意服务器文件路径；音频和视频资产视图不各自实现文件读取。
- 直接使用原始修订版、未来转码得到的媒体以及字幕转换结果都表现为播放呈现。它默认只在播放期间存在或作为可回收缓存复用，不会自动成为正式产物；只有另一项明确的保留、整理或导出操作可以将输出持久化。
- 播放端声明自身支持能力和用户选择的音轨、字幕或质量偏好，由应用层自动生成播放计划；直接播放优先，普通用户不选择处理器或编辑处理步骤。媒体与字幕可以有各自的有序处理路径，V1 不建立通用 DAG 或用户可编程媒体管道。
- 应用层与交付层的播放路径从首个切片起保持媒体中立；DLsite 音声负责完成第一条真实用户旅程，兼容的视频可以复用相同路径，不兼容的视频返回明确原因。普通播放不建立持久播放会话或工作流执行；暂停、切换文件、播放结束和页面隐藏时保存有产品意义的交互状态，V1 不要求定时轮询同步。
- 首个播放切片强制验收真实语料中的 MP3 与 WAV；MP4 可用于验证共享读取路径，但不扩大为完整视频兼容承诺。播放计划保留独立字幕路径，LRC 与 VTT 仍可出现在作品文件树中，但 V1 不要求自动配对或同步显示；资产展示不通过同名或目录邻近自行建立音频与字幕关系，后续必须由适用目录或格式能力提供明确配对证据。
- 转码、字幕转换、BDMV 菜单、DRM、远程串流和复杂播放列表不属于首个播放切片，但播放准备结构不能阻止以后增加这些能力。

## 暂不作为发布门槛

- 完整播放器或阅读器生态，以及对所有容器、编码和字幕格式的兼容。
- 浏览器内联打开原文件、内建书籍阅读器、阅读进度、书签和批注。
- 账户管理、权限模型和面向公网的安全加固。
- 运行时安装第三方插件或动态兼容性协商。
- 覆盖所有未来数字资产种类。

本文只记录产品范围和可验收结果。领域语言由各上下文的 CONTEXT 文档维护，架构取舍由 ADR 维护；实现包、组件库和路由结构不在本文中定义。
